# Holochain 0.7 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move both Edge Node container images (`edgenode`, `edgenode-harvester`) from Holochain 0.6.1 to Holochain 0.7.0, with the hApp tooling, test suite, and docs working against 0.7, and with the version pinned in one place so the follow-up bump to 0.7.1 is a two-line change.

**Architecture:** The images download prebuilt `holochain` and `hc` binaries at build time and drive the conductor over its admin websocket using the `hc` CLI from shell scripts (`happ_tool`, the harvester's s6 `run` script). The upgrade is therefore three things: a new conductor config template that 0.7 accepts, a rewrite of every `hc sandbox call` invocation to the new `hc client` command group, and a new 0.7-built test hApp (ziptest) because none of the current fixtures (kando, relay) have 0.7 builds. Companion components are taken from their in-progress 0.7 branches where they exist locally (`../log-harvester`, `../log-sender`) and bumped or pinned otherwise.

**Tech Stack:** Docker (wolfi-base, s6-overlay), bash, jq, bats, Holochain 0.7.0 release binaries, Node (log-harvester), Rust (happ_config_file, log-sender), OpenTofu/cloud-init templates (docs and env plumbing only).

**Spec:** This plan carries its own design. The "Design decisions" section records what was decided during brainstorming and the adjustments the user made on 2026-09-03; there is no separate spec file.

## Global Constraints

- Target Holochain release: `0.7.0` (tag `holochain-0.7.0`, published 2026-07-30). A `0.7.1` release is expected imminently; `0.7.1-rc.0` was tagged 2026-09-02 with no binary assets. Every place the version appears must be a single `ARG` per Dockerfile so the 0.7.1 bump is Task 11.
- Binary download URL pattern is unchanged: `https://github.com/holochain/holochain/releases/download/holochain-${VERSION}/holochain-${ARCH}` and `.../hc-${ARCH}` for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`.
- 0.7 conductor config uses `deny_unknown_fields`. `network.signal_url` and `network.webrtc_config` must not appear.
- In 0.7 the kitsune2 bootstrap server also serves the iroh relay, so `network.relay_url` is set to the same URL as `network.bootstrap_url`: `https://dev-test-bootstrap2.holochain.org`. (`hc sandbox generate ... quic <url>` in 0.7 does exactly this; unyt's `conductor-config.sh` in `../log-harvester` uses the `<bootstrap>/relay` form, which reaches the same axum route.)
- 0.7 removes `hc sandbox call`, `hc sandbox zome-call`, `hc sandbox zome-call-auth`. Replacements are `hc client call -p <port> <request>`, `hc client zome-call -p <port> ...`, `hc client zome-call-auth -p <port> ...`. The old `-r/--running` flag is now `-p/--port`.
- `hc client call -p <port> install-app` keeps the same argument shape: `--app-id`, `--agent-key`, positional bundle path, optional positional network seed. `add-app-ws <port> --allowed-origins <origins>` attaches an app interface.
- `hc client call -p <port> list-apps` prints a JSON array. Each element has `installed_app_id` and `cell_info` shaped `{ "<role>": [ { "type": "...", "value": { "cell_id": { "dna_hash": "uhC0k...", "agent_pub_key": "uhCAk..." } } } ] }`. `new-agent` prints a JSON string, for example `"uhCAk..."`.
- There is no data migration from 0.6.x to 0.7.x. Conductor databases were renamed and now live flat under `<data_root_path>/databases/` as `conductor.db`, `wasm.db`, `dht-<dna_hash>.db`, `p2p-peer-meta-<dna_hash>.db`. Any existing `/data` volume must be reset before running 0.7 (Task 9 settles the lair keystore question).
- Test fixture hApp: ziptest v0.6.0-dev.0 (built for Holochain 0.7, release notes "release compatible with final holochain 0.7"). The release ships only a `.webhapp`:
  - `https://github.com/holochain-apps/ziptest/releases/download/v0.6.0-dev.0/ziptest.webhapp` sha256 `271367169b5ab3e8ec73ae8bd9118b841d000733a5315fbf39dbd0c7a27bde1e`
  - the `ziptest.happ` inside it has sha256 `4da017a73dee5e857448b9075a801e23029ab58d4acee50a1f9ae6d7557bb8f3`
  - single role `ziptest`; coordinator zome `ziptest` exposes `create_thing({thing: {content: String}, bunch: String, reps?: u32, tag?: String})`.
- Harvester hApp: unyt v0.104.0 (`https://github.com/unytco/unyt-sandbox/releases/download/v0.104.0/unyt.happ`, sha256 `6f03f9416b0279e52f673968faf188a16dde620ae9c0425049397e8eb0e890a5`). Everything from v0.101.0 on is a 0.7 build.
- log-harvester source: `unytco/log-harvester` branch `feat/adapt-to-holo-hosting-agreement` (contains the 0.7 migration commits plus the holo-hosting agreement work: `--lane` is required by `init`, `whoami` subcommand added, app interface must be attached by the caller with `add-app-ws`). The local checkout at `../log-harvester` is on that branch.
- log-sender: v0.1.5 has no Holochain crate dependencies and needs no rebuild to run beside 0.7, but its database-size metering reads `<data_root_path>/databases/dht/`, a directory that no longer exists in 0.7 (Task 6b).
- `@theweave/wdocker`: `0.16.0-dev.4` (published 2026-09-02, depends on `@holochain/client ^0.21.0`).
- Commit messages follow the repo's `type(scope): summary` style. No co-author footers.
- All local test runs go through `docker/run_tests_multi.sh` (edgenode) and `docker/run_harvester_tests.sh` (harvester). Both need Docker, and the harvester runner needs the log-harvester source (local checkout or `GITHUB_TOKEN` for the private repo) and `GITHUB_TOKEN` for `unytco/log-collector`.

## Design decisions

1. **0.7.0 now, 0.7.1 immediately after.** 0.7.0 has binaries; the rc does not. Task 11 is the follow-up and lists every file the bump touches.
2. **Relay URL equals bootstrap URL.** The 0.7 bootstrap server hosts the iroh relay. The template carries both fields explicitly (the conductor defaults to the n0 canary relay otherwise).
3. **Rename the CLI calls, keep the script structure.** `happ_tool` and the harvester `run` script keep their control flow. The 0.5.6 regex fallback in `extract_dna_hash` is deleted because 0.7's JSON shape matches what the jq path already expects.
4. **ziptest replaces every fixture.** ziptest v0.6.0-dev.0 is 0.7-built and public. It ships only a `.webhapp`, so all fixtures use that URL and `happ_tool`'s webhapp-extraction path; the `.happ`-URL tests become URL/checksum tests over the same asset. The "bad URL" fixture points at the non-existent `ziptest.happ` asset. Because ziptest has a trivial `create_thing` zome function, `multi_install.bats` (skipped since 0.6.0) can be re-enabled with an `initZomeCalls` fixture.
5. **Harvester follows unyt's own 0.7 Docker entrypoint.** `../log-harvester/docker-entrypoint.sh` is the reference: `hc client call --port`, explicit `add-app-ws`, `--lane` from `LANE_DEFINITION_IDS`, optional unit-index and period args, init retried three times. The edgenode s6 script mirrors it. `UNYT_HAPP_VERSION` is pinned (the current `releases/latest` pull has been a 0.7 hApp since 2026-08-13, so the 0.6.1 harvester image is already broken).
6. **Companion binaries.**
   - `h2hc-linker` `main` is on holochain 0.7 crates at version 0.2.0 but has no release tag (latest v0.1.2, built against 0.6). Task 6a is gated on that release.
   - `log-sender` needs a one-function fix for the 0.7 database layout, made in `../log-sender` and released as v0.1.6. Task 6b. Until then db-size proofs fail non-fatally (the service logs "Error reporting db sizes" and keeps sending fetchedOps).
   - `wdocker` goes to 0.16.0-dev.4 and the `jq` dependency-rewrite hack is dropped (0.16.x publishes real semver ranges).
   - `happ_config_file` becomes 0.4.0: `holo_hash` 0.7.0, `--webrtc` and WebRTC fields removed from templates, still tolerated by `validate`. Separate release tag, so its own task.
7. **Old config templates stay.** `conductor-config-0.5.6` and `-0.6.0` were kept through the last two upgrades. Follow the precedent.
8. **Upgrade procedure is documented, not automated.** Deployed nodes need a volume reset. Whether the lair keystore directory can be carried across is undocumented upstream, so Task 9 is a spike whose result is written into `deploy/DEPLOYMENT.md`.

```bash
#!/command/with-contenv /bin/sh
set -e

APP_ID="${HC_APP_ID:-unyt}"
NETWORK_SEED="${HC_NETWORK_SEED:-network-seed}"
LOG=/data/logs/startup.log

# Admin calls against the local conductor (hc 0.7: `hc client call`)
hc_admin() {
  hc client call -p "${HC_ADMIN_PORT}" "$@"
}

# Wait for holochain conductor to be ready
echo "Waiting for holochain conductor..." >> "$LOG"
while ! hc_admin list-apps > /dev/null 2>&1; do
  sleep 5
done
echo "Holochain conductor is ready." >> "$LOG"

# Install unyt.happ if not already installed
if [ -f "${HAPP_PATH}" ]; then
  if ! hc_admin list-apps 2>/dev/null | grep -q "\"${APP_ID}\""; then
    echo "Installing ${APP_ID} happ..." >> "$LOG"
    hc_admin install-app "${HAPP_PATH}" --app-id "${APP_ID}" "${NETWORK_SEED}" >> "$LOG" 2>&1 || true
    hc_admin enable-app "${APP_ID}" >> "$LOG" 2>&1 || true
  fi
else
  echo "WARNING: ${HAPP_PATH} not found - skipping happ install" >> "$LOG"
fi

# Attach the app websocket the harvester connects to. The 0.7 log-harvester
# no longer attaches it itself. Idempotent: a second attach on the same port
# fails and is ignored.
hc_admin add-app-ws "${HC_APP_PORT}" --allowed-origins "log-harvester" >> "$LOG" 2>&1 || true

# The holo-hosting agreement pins parks and executions to lane definition
# hashes; init needs at least one. LANE_DEFINITION_IDS is comma or space
# separated. UNIT_INDEX_* and INVOICE_PERIOD_MS are optional overrides.
LANE_ARGS=""
for lane in $(echo "${LANE_DEFINITION_IDS:-}" | tr ',' ' '); do
  LANE_ARGS="$LANE_ARGS --lane $lane"
done
EXTRA_ARGS=""
[ -n "${UNIT_INDEX_STORAGE:-}" ] && EXTRA_ARGS="$EXTRA_ARGS --unit-storage ${UNIT_INDEX_STORAGE}"
[ -n "${UNIT_INDEX_GOSSIP:-}" ] && EXTRA_ARGS="$EXTRA_ARGS --unit-gossip ${UNIT_INDEX_GOSSIP}"
[ -n "${INVOICE_PERIOD_MS:-}" ] && EXTRA_ARGS="$EXTRA_ARGS --period-ms ${INVOICE_PERIOD_MS}"

# init, retried to ride out conductor/lair startup races (as unyt's own
# docker-entrypoint.sh does)
run_init() {
  for attempt in 1 2 3; do
    if node /app/dist/log-harvester.js init \
        --config "${CONFIG_PATH}" \
        --url "${COLLECTOR_URL}" \
        --admin "${ADMIN_SECRET}" \
        --hc-admin "${HC_ADMIN_PORT}" \
        --hc-app "${HC_APP_PORT}" \
        --app-id "${APP_ID}" \
        $LANE_ARGS $EXTRA_ARGS >> "$LOG" 2>&1; then
      return 0
    fi
    echo "harvester init failed (attempt $attempt of 3)" >> "$LOG"
    sleep 3
  done
  return 1
}

# Wait a moment for keystore to be fully ready before touching credentials
sleep 3

# Initialize config on first run; refresh credentials on restart
if [ ! -f "${CONFIG_PATH}" ]; then
  echo "Initializing harvester config..." >> "$LOG"
  run_init || { echo "harvester init failed; not starting harvester" >> "$LOG"; exec tail -f /dev/null; }
  chown nonroot:nonroot "${CONFIG_PATH}" 2>/dev/null || true
else
  echo "Refreshing harvester credentials..." >> "$LOG"
  cp "${CONFIG_PATH}" "${CONFIG_PATH}.backup"
  LAST_INVOICE=$(jq -r '.lastInvoice // empty' "${CONFIG_PATH}" 2>/dev/null || true)
  rm "${CONFIG_PATH}"
  if run_init; then
    rm -f "${CONFIG_PATH}.backup"
  else
    mv "${CONFIG_PATH}.backup" "${CONFIG_PATH}"
  fi
  if [ -n "${LAST_INVOICE}" ]; then
    jq ".lastInvoice = ${LAST_INVOICE}" "${CONFIG_PATH}" > "${CONFIG_PATH}.tmp" && \
      mv "${CONFIG_PATH}.tmp" "${CONFIG_PATH}" || true
  fi
  chown nonroot:nonroot "${CONFIG_PATH}" 2>/dev/null || true
fi

# Log the agent key the agreement must authorize (whoami is new in the 0.7 branch)
node /app/dist/log-harvester.js whoami --config "${CONFIG_PATH}" >> "$LOG" 2>&1 || true

echo "Starting log-harvester service..." >> "$LOG"

TODAY_FLAG=""
if [ "${LOG_FOR_TODAY:-false}" = "true" ]; then
  TODAY_FLAG="--today"
fi

exec gosu nonroot node /app/dist/log-harvester.js exec \
  --config "${CONFIG_PATH}" \
  --loop \
  ${TODAY_FLAG} >> /data/logs/log-harvester.log 2>&1
```
